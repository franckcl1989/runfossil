# Release Readiness

## Purpose

This document records the hardening gates required before a `runfossil` release.
It distinguishes repository-automated validation from validation that must be
run in a real privileged Linux environment.

## Automated Local Gates

Run these from the repository root:

```text
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo check --workspace --all-targets
cargo test --workspace
cargo deny check bans licenses sources
```

The `cargo deny` command requires a local `cargo-deny` installation. CI runs the
same dependency policy through `EmbarkStudios/cargo-deny-action`.

## Static Release Artifact

The release binary target is:

```text
x86_64-unknown-linux-musl
```

Build and verify it locally with:

```text
rustup target add x86_64-unknown-linux-musl
bash scripts/build-static-release.sh
```

The script requires a musl linker such as `musl-gcc`, verifies that `file(1)`
reports a statically linked or static PIE binary, verifies that `ldd` does not
report dynamic dependencies, and writes `runfossil.sha256` next to the binary.

CI has a `release-static` job that installs `musl-tools`, builds the musl
release binary, verifies static linkage, writes a checksum, and uploads the
binary plus checksum as workflow artifacts.

## Signature and Artifact Verification

Release artifacts must have:

- a static `runfossil` binary;
- a matching `runfossil.sha256` checksum;
- a detached signature generated by the release signer;
- a verification record showing the checksum and signature were checked.

Verify a released artifact with:

```text
bash scripts/verify-release-artifact.sh runfossil runfossil.sha256 runfossil.asc
```

The repository cannot generate a real release signature without the release
signing key. Unsigned artifacts must not be described as signed releases.

## Production Validation

The following gates require real target environments and must be recorded before
release:

| Gate | Required result | Status |
|---|---|---|
| Root production-like capture | `runfossil capture` runs as effective UID 0, preserves a complete or explicitly partial snapshot, and does not require packaging before recovery. | not run in this workspace |
| Cross-distribution compatibility | Capture, pack, inspect, static binary execution, and failure handling are exercised on the release matrix. | not run in this workspace |
| Performance benchmark run | Store and pack benchmarks are run on release hardware or a documented baseline host. | not run in this workspace |
| Artifact signing and verification | Release binary checksum and detached signature are generated and verified. | requires release signing key |

Minimum compatibility matrix:

| Distribution | Version | Architecture | Kernel | Validation |
|---|---|---|---|---|
| Debian | stable | x86_64 | distro default | pending |
| Ubuntu | LTS | x86_64 | distro default | pending |
| Fedora | current | x86_64 | distro default | pending |
| Rocky or AlmaLinux | current major | x86_64 | distro default | pending |

Benchmark commands:

```text
cargo bench -p runfossil-store
cargo bench -p runfossil-pack
```

Release notes must distinguish implemented behavior, exclusions, deferred work,
and validation actually run.
